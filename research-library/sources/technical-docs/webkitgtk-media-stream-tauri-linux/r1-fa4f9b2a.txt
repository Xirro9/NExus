WebKitGTK ships media-stream disabled by default: navigator.mediaDevices does not exist at all (rcq-desktop DESKTOP.md states it explicitly). Upstream webkitgtk.org still says 'Currently we are working to finish support for WebAudio and WebRTC'. A WebKitSettings:enable-webrtc property exists (>=2.42) and implies enable-media-stream, but Tauri/wry exposes NO supported toggle; apps that got it working patched runtime config themselves (KittyCAD modeling-app issue #625); tauri issue #8851 ('webkitgtk doesn't support webrtc yet') was never resolved with first-party support. Even when capture works it rides GStreamer + PipeWire inside WebKit; media PLAYBACK needs system GStreamer plugins (good/bad/ugly) of matching ABI. AudioWorklet reliability in webkit2gtk-4.1 on Ubuntu 24.04: UNVERIFIED/unreliable. Production conclusion: production Tauri Linux voice apps (Handy) capture Rust-side via cpal and play back via rodio, never through the webview.
